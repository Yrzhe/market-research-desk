RESEARCH NOTE / SYSTEM DESIGN

为什么研究台
要保留一部分历史

要快速看懂今天发生了什么，也要能在几个月后复原当时依据。数据需要分层保留，计算则随任务安排。

发表 2026.10.30数据时点 2026.10.30类别 系统研究 · 固定版本
CONTENTS研究目标何时计算存储分层容量算例试点与待验证来源
核心判断

首页应该读已经核验的数据；后台持续取得增量；报告固定发表时的证据与口径。这样，最新图和旧判断才能同时可信。

01 / PURPOSE

每天要回答的四个问题

这座研究台服务于一个决策过程：最近哪些市场、板块和主题发生变化？哪些标的值得继续研究？重大事件的证据从哪里来？当时的判断后来是否成立？

01 / 发现

先看变化

跨市场识别异常与缺失；每个数字附单位、来源和观测时点。

02 / 研究

再追证据

沿标的、主题和事件进入财务事实、披露与相反证据。

03 / 复盘

保存判断

记录报告发表版本和复核日期，避免后来数据覆盖当时结论。

02 / COMPUTATION

即时计算有边界

筛选、同比和图表显示可在打开网页时计算。前提是输入数据已到达、单位与报告期一致，且公式版本已确定。采集、事件去重、全市场扫描和深度研究适合在后台增量执行，并留下运行结果。

数据流
许可来源行情 / 披露 / 授权资讯
后台采集增量 / 去重 / 失败记录
事实与计算历史版本 / 汇总缓存
网页与报告最新视图 / 发表快照

旧报告里的关键图表默认保持发表时的数据和结论。若用户要看今天的同一公式，应明确切换至最新视图，并显示两者的时间差。

03 / RETENTION

三层存储，各有保留理由

层级保留什么处理方式
长期事实财务事实及更正、许可范围内的日线、关键事件索引、报告与判断版本D1 存可查字段；合法的大文件才进入 R2，记录来源与许可
可重算结果筛选分数、板块排名、图表采样序列随输入更新失效；保留计算公式版本
短期材料下载缓存、重复新闻、解析文本和详细日志试点候选清理期 7–30 天，按来源许可调整
不能因为文件在网上能看到，就默认可以长期复制新闻正文或 PDF。报告可保留合法摘要、出处链接与经过核验的事实。
04 / SCALE

真正膨胀的是未经筛选的全文

以下是规划用的容量假设，不是当前占用。日线按 500 个标的、每年 252 个交易日、保留十年且每行 200 字节估算；全文按每天 1,000 份、每份 2 MB、保存一年估算。

Cloudflare D1 有单库容量及读写配额，R2 按存储与操作计费。历史持续增长时，可将不常查询的旧块压缩归档，保留可检索索引，而不是无限扩大在线明细库。

05 / VALIDATION

接下来用真实运行纠正假设

试点先覆盖少量来源和标的，连续运行 30 天，观察存储增长、D1 读写行数、对象请求、采集失败、重算耗时和实际阅读路径。A 股、港股及新闻自动化需要分别确认稳定来源与使用权。

本报告是系统方案，不包含投资建议，也不代表四个市场的数据已接入。研究台当前只试采集部分 SEC 披露与 Binance 现货日线。
