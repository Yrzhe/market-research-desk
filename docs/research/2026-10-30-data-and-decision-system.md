# 从可获得的数据出发：市场研究台的数据与运行方案

调研日期：2026-10-30。本文为数据源核查和系统设计输入，不代表已接入实时数据。当前仓库只有可配置的数值监控、运行归档和明确标记的合成预览；没有全市场行情、新闻处理、自动选股或 Cloudflare 数据库。[现有能力](../../README.md)。

## 先确定要回答的决策问题

每天打开研究台，应先知道：哪些市场和板块出现了值得检查的变化；变化是否来自可靠且新鲜的来源；哪些候选标的值得深入；一家公司最近的经营、估值、价格和事件怎样变化；昨天的判断是否被新证据推翻。首页需要的是可追溯的异常与趋势摘要，公司页需要能向下追到原始披露、计算口径和反证。历史数据用于比较、验证计划可信度和判断趋势，不把旧新闻堆成当日结论。

「Fish Cal / Fish Cal AI」的名称尚未确认。按功能相似度，[Fiscal.ai 的官方 API 文档](https://docs.fiscal.ai/docs/introduction)是本轮参考：它列出财务报表、比率、分部与经营 KPI、价格、新闻、事件、披露和电话会等不同数据集。这说明专业界面需要多层数据；不能据此假定每家公司、每个市场都能免费取得全部字段。其分部/KPI、持有人、会议记录等数据集有覆盖范围限制；[试用计划](https://docs.fiscal.ai/docs/guides/free-trial)也有公司和请求配额。

## 公司数据的可获得性

「可查看」表示源头存在；「已试取」只表示本机在 2026-10-30 成功读取一次；「可自动入库」还需要逐源确认许可、字段和稳定性。下表没有一项已经接入本产品。

| 数据层 | 可取得的具体字段 | 核查结果与约束 | 研究台应如何使用 |
| --- | --- | --- | --- |
| 身份与分类 | 公司名、代码、交易所、行业、上市状态；加自定义主题标签 | [SEC submissions API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)含美股申报人名称、旧名、交易所与代码；A/HK 须按交易所或授权供应商映射；跨市场行业口径不能直接混用 | 稳定 asset ID、代码历史、市场、行业口径和来源版本 |
| 财务报表 | 营收、利润、资产负债、现金流、每股数据、报告期间、币种 | SEC [CompanyFacts](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)公开标准 XBRL 事实，且不含公司自定义扩展事实。本机试取 Apple CompanyFacts 返回 200、约 3.79 MB、503 个 us-gaap tag；tag 数不等于可直接展示的指标数。A 股 [巨潮资讯](https://list.cninfo.com.cn/cninfo/)可查公告，本机试取[比亚迪三季报 PDF](https://static.cninfo.com.cn/finalpage/2026-10-30/1225641442.PDF)返回 200、365,383 字节。[上交所说明](https://www.sse.com.cn/disclosure/listedinfo/listedcompanies/)要求以正式 PDF 为准。港股 [HKEXnews](https://www.hkexnews.hk/index.htm?sc_lang=en)可人工检索报告，本机试取[腾讯中期报告 PDF](https://www1.hkexnews.hk/listedco/listconews/sehk/2026/0825/2026082500556.pdf)返回 200、5,135,808 字节 | 按报告期及披露日存事实，保存单位、会计口径、原文定位和更正版本；不把财报日期误标为今日 |
| 公司经营指标 | 用户数、销量、订单、门店、分部收入、管理层指引等 | 因公司和行业而异，多存在财报正文、投资者关系材料。Fiscal.ai [分部与 KPI](https://docs.fiscal.ai/docs/introduction)并非全公司覆盖。PDF 可见不等于可可靠自动抽取 | 每家公司建立带出处的指标字典，记录定义与口径变化；不可用字段显示「未覆盖」 |
| 行情与估值 | 日线/分钟线、成交额、成交量、复权、股本、市值、估值倍数 | 各交易所和供应商的数据权利不同。[上交所信息服务](https://www.sse.com.cn/transparency/services/index.shtml)与 [HKEX 行情 FAQ](https://www.hkex.com.hk/Global/Exchange/FAQ/Market-Data?sc_lang=en)涉及授权。SEC 披露 API 不是行情 API。实时、历史与再展示权应单独核对 | 先定可靠的日线供应商和许可，再计算趋势、收益、估值；供应商断流时显示时点和故障 |
| 公告与公司行为 | 财报、回购、分红、拆股、融资、管理层变动、重大合同 | 美股 SEC 申报元数据适合自动增量发现；A 股有正式公告；港交所文件可人工查看，但[HKEXnews 条款](https://www2.hkexnews.hk/Global/Exchange/Terms-of-Use?sc_lang=en)限制程序化访问、系统性汇编、网络服务器存储以及文本/数据挖掘，需许可或替代授权源 | 事件索引保存标题、发布时间、公司、类型、来源 URL、版本；仅对允许处理的正文做抽取 |
| 新闻与研报 | 标题、发布时间、媒体、关联实体、主题、摘要、原文链接 | [GDELT DOC API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)可提供新闻发现与趋势线索；本机请求遇到速率限制，不能视作覆盖保证。新闻正文和卖方研报需要各自的使用权 | 先索引链接和合法元数据，去重成事件；只在许可允许时保留正文或全文索引 |
| Web3 资产 | 交易对、交易所、K 线、链、协议、代币、流通量、链上活动 | [Binance Spot API](https://developers.binance.com/en/docs/products/spot/rest-api)提供某交易所的交易数据；本机 BTCUSDT 日 K 请求返回 200、2 条记录。单一交易所价格不等于全市场，协议收入、TVL、链上行为需要另选来源和核对定义 | 将 token、上市公司、协议、链分别建实体，以主题和生态关系统一发现，不把 token 的市值/收入与股票财务指标混排 |

港交所限制尤其关键：本报告记录了人工可见和单次读取证据，**不建议据此编写 HKEXnews 自动抓取器**。先确认授权数据源或取得书面许可，再纳入自动事件流水线。

以单家公司为单位做接入验收时，还需核对这些容易被「财务数据已覆盖」掩盖的字段：

| 信息包 | 字段与计算口径 | 当前把握 |
| --- | --- | --- |
| 报表与质量 | 营收、毛利、费用、净利、经营现金流、资本开支、应收、存货、现金、债务；同比、环比、TTM；报告原值和调整值分开 | 美股标准 XBRL 可作为起点，仍需处理申报期间、币种、重述和自定义披露；A/HK 需逐公司抽取和核验 |
| 估值与股本 | 股价、流通/总股本、市值、企业价值、PE/PS/PB、自由现金流收益率、分红、回购、拆股、稀释 | 依赖合法行情、股本和公司行为数据，分母的报告期与价格时点要对齐；当前无供应商 |
| 经营与计划 | 分部收入/利润、地域、客户/用户/销量/产能、订单、管理层目标、资本开支计划 | 公司自定义，覆盖率无法事先承诺；须建立每个指标的定义、单位、披露频率和原文位置 |
| 所有权与治理 | 主要股东、内部人交易、机构持仓、董事高管、关联交易、质押等 | 美股 SEC 文件提供原始披露路径；跨市场标准化与更新频率不同。Fiscal.ai 的持有人产品[目前仅美股覆盖](https://docs.fiscal.ai/docs/introduction) |
| 市场预期 | 卖方一致预期、目标价、盈利预测修订、财报超预期 | 通常为有许可的增值数据。Fiscal.ai 文档也把街头一致预期限定为主要在美国上市且被供应商覆盖的公司；不能从公开财报倒推出「市场预期」 |
| 替代与草根证据 | 产品价格、销量、门店、招聘、应用排名、搜索需求、社交口碑 | 只适合按具体行业设实验口径；来源噪声、样本偏差和平台条款要逐项审核，不能直接替代公司财报 |
| 风险与催化 | 监管、诉讼、融资、供应链、产品发布、财报日期、政策变化 | 事件必须保留发生时间、首次报道、正式确认、影响对象和反证；「可能影响」是分析判断，不是已发生的价格因果 |

这些字段不是每家公司都有的固定列。接入记录应以 `字段 × 公司 × 市场 × 来源` 为单位标记覆盖、时效、使用权和可信度；读者才能看出「缺失」是没有披露、未购买数据，还是采集失败。

## 自动运行与可见过程

把全市场发现和单标的深研分开，避免每天为所有公司解析全部原文。

1. **发现层**：按市场日历采集获许可的行情、披露索引和新闻线索；记录水位线、成功/失败、耗时、来源延迟、重复率。新候选的初筛使用当期客观数据和公开事实，先冻结候选集，再读取已有关注名单与旧判断，以免旧结论锁定搜索范围。
2. **事件层**：同一事件的多篇新闻聚合；按实体、主题、事件类型与发生时间关联。保留原始链接、发布时间、事实摘录、反证、冲突、修订记录和处理版本。AI 摘要必须指向来源，不把热度或情绪当事实，也不把相关性当因果。
3. **深研层**：用户点选候选标的后，补齐近年财务、近期经营指标、同业比较、公司计划、事件时间线和关键反证；生成「目前判断、尚缺证据、可证伪条件、下次复核时间」，由人确认研究结论。
4. **展示层**：运行页显示每个任务的 `排队 → 抓取 → 解析 → 去重 → 核验 → 汇总 → 完成/失败`，同时显示覆盖数、进度、耗时、重试、丢弃原因和最后成功时间。首页只取新鲜、可追溯的结果，失败与未覆盖不能变成「0」。

计划中的核心对象：`instrument`（可交易标的）、`entity`（公司/协议/链）、`sector_taxonomy`、`theme_membership`、`observation`（值+单位+期间+来源）、`document_reference`、`event`、`event_evidence`、`run`、`source_attempt`、`research_decision`。每条观察和结论都要有来源、采集时刻、原始发生/披露时刻、许可状态和处理版本。

板块按市场选择清楚的行业分类及其版本，展示板块内涨跌分布、成交、估值分布、财报变化、事件密度、强弱与成员贡献。Web3 采用横跨资产类型的主题层，如「稳定币、交易所、链基础设施、矿业」；每个主题可同时包含股票、token、协议，并注明关联证据、有效期、相关程度。跨股票/token 只比较有共同定义的价格和风险指标，专属经营数据分栏呈现。

## 数据会不会爆炸

真正扩容快的是原始文件、重复新闻和高频逐笔数据；日级结构化指标通常小得多。以下是**容量演算假设，不是实际监控量或报价**：1,000 家公司 × 20 个指标 × 每天 1 条 × 365 天 = 730 万条指标/年。若每条连同索引平均占 200 字节，约 1.46 GB/年；真实库大小要用试运行测量。另一方面，每天保存 1,000 份平均 2 MB 的全文，就是约 730 GB/年。两种策略差两个数量级。

建议保留：结构化事实及修订历史长期保存；新闻仅保留合法元数据、去重后的事件与链接；短期原始抓取缓存按来源许可和失败复核需要设期限；只对选中深研标的保存许可允许的原文；昂贵分钟线设窗口或降采样成日线。使用内容哈希去重、增量同步、水位线、压缩、分区和生命周期删除。删除策略须保留研究结论所引用的事实与来源指针，不能使旧判断失去证据。

上述 730 万条/年约为每天 20,000 次新指标写入，尚未算索引写入、事件、运行日志和更正；因此不能仅看磁盘 GB。试运行要同时量化 `GB/月、写入行/日、读取行/日、对象请求/月、每个数据源费用、AI 处理量`，按 P50/P95 与高峰日估算。大规模全市场分钟线会使模型完全不同，第一阶段不纳入。

## VPS + Cloudflare：适合，但有边界

建议 VPS 跑调度、下载、PDF 解析、事件聚类和模型任务；经鉴权的写入 API 把结构化结果送入 Cloudflare D1，许可允许的原始文件选择性存入私有 R2；Cloudflare Worker 负责轻量写入、查询和鉴权，前端显示结果及运行日志。VPS 保留重试队列与原始处理日志，并做恢复演练。R2 对象不设公开桶，研究台加 Cloudflare Access；服务间用服务凭证而非浏览器持有写入密钥。[Access 服务令牌](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)、[D1 Worker 绑定](https://developers.cloudflare.com/d1/worker-api/)、[R2 Worker 绑定](https://developers.cloudflare.com/r2/get-started/workers-api/)。

Cloudflare 并非无限容量，也不是主要靠 R2 出站收费。按 2026-10-30 官方文档：

| 产品 | 当前关键限制与计费 | 对本方案的含义 |
| --- | --- | --- |
| [R2 Standard](https://developers.cloudflare.com/r2/pricing/) | 每月免费 10 GB-month、100 万次 Class A、1,000 万次 Class B；超额存储 $0.015/GB-month，写类操作 $4.50/百万，读类 $0.36/百万；R2 出站免费。低频存储另有取回费，免费额度仅适用 Standard | 文件容量可随付费增长，成本要加操作数；直接出站不是主要收费项 |
| [D1](https://developers.cloudflare.com/d1/platform/limits/) | 免费每库 500 MB、账户 5 GB；付费每库 10 GB、账户 1 TB，单行/BLOB 最多 2 MB；[免费日配额](https://developers.cloudflare.com/d1/platform/pricing/)为 500 万行读、10 万行写，付费按月含 250 亿行读、5,000 万行写，超额计费 | D1 存索引与结构化数据，不能当无限制 PDF 仓库；二级索引也增加写入与存储 |
| [Workers](https://developers.cloudflare.com/workers/platform/pricing/) | 免费请求与 CPU 有配额；付费计划有月费和超额计算 | 重度解析和长任务留在 VPS，Worker 只做接口与轻处理 |

如果只按上面假设的 730 GB 原文堆积计算，单看 R2 Standard 的**第 12 个月末**静态占用，扣除 10 GB 免费额后的名义存储费约 `720 × $0.015 = $10.80/月`；实际按 GB-month 用量、计费进位和操作数计算，未计 VPS、数据许可、模型、备份和带宽的其他环节。这是解释规模的算例，不是预算承诺。更值得优先解决的是数据权利、质量和处理成本。

## 在排版前要通过的验证门槛

第一轮选 A 股、港股、美股、Web3 各 5 个不同类型标的，逐一列出实际可取得字段、数据源、许可、历史深度、更新时间和缺口；再覆盖至少一个重度事件（如财报修订或重大监管变化）追踪原文、影响链、反证与版本。跑 30 天只读试采集，记录上述成本和质量指标，给每个数据模块打 `已接入 / 已验证可接入 / 需授权 / 暂不可得` 状态。只有通过这些门槛，才确定首页、板块、标的和事件页各自的图表密度与颜色规则。当前产品没有这些实时数据，不能用合成曲线代替验证。
